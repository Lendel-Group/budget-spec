# Правила для ИИ-агентов

Этот репозиторий — спецификация, а не приложение. Кода приложения здесь нет.

## Когда работаешь в этом репозитории
- Язык документов — русский. Тексты интерфейса в `spec/` — **точные**, их копируют в приложения дословно.
- `fixtures/*.json` руками не править: только через `tools/cases.ts` и генерацию из PWA (`tools/README.md`).
- Меняя формат бэкапа, обновить вместе: `spec/04-backup-format.md`, `schema/`, случаи `parseBackup` в `tools/cases.ts`.
  Несовместимое изменение — только с новой `schemaVersion` и миграцией старой версии при импорте.
- Каждое изменение поведения записывать в `CHANGELOG.md` (раздел «Не выпущено»).
- Не добавлять в спецификацию ничего, что требует сервера, аккаунта или сбора данных (см. принципы в `spec/00-overview.md`).

## Когда реализуешь платформу по этой спецификации (например, Android на Kotlin)
- Прочитать `spec/00` … `spec/06` целиком до начала работы.
- Каждую функцию из `spec/02-business-rules.md` реализовать как чистую функцию без зависимостей от UI и БД
  и покрыть тестами, которые читают `fixtures/<модуль>.json` (подключить этот репозиторий как git submodule
  или копировать `fixtures/` скриптом — но не переписывать вручную).
- Числа: double + `round2` с семантикой JS `Math.round` (см. `spec/02`, раздел «Округление»). Не использовать
  `kotlin.math.round` и `BigDecimal` с другим режимом округления.
- Форматирование чисел сверять с `fixtures/format.json` (неразрывный пробел U+00A0 в тысячах).
- Экспорт/импорт бэкапа — строго по `spec/04` и `schema/`. Обязательный тест: файл из PWA импортируется, а
  экспортированный файл проходит проверку `parseBackup`-фикстур.
- Всё, что в `spec/06-platforms.md` отмечено «только PWA», не переносить.
- Если спецификация неполна или противоречит фикстурам — не угадывать: свериться с кодом PWA
  (`al-writer/PWA-Budget`, `src/domain`, `src/services`) и предложить исправление спецификации.
