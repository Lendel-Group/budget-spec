# 03. Операции над данными

Что делает каждое действие пользователя с хранилищем. Эталон — `src/services/*.ts` в PWA.
**Каждая операция атомарна:** при любой ошибке не меняется ничего (одна транзакция БД).
Тексты ошибок показываются пользователю как есть.

## Запуск приложения
1. **Сид**, один раз за жизнь данных (если нет `config.seeded`): счёт «Наличные KZT» (`cash`, KZT, остаток 0)
   и стандартные категории ([01](01-data-model.md#стандартный-набор-сид)), затем `seeded = true`.
2. **Первые шаги**: если `config.onboarding` ещё нет — `active`, когда операций нет (свежая установка),
   иначе `dismissed`. Повторно не меняется.
3. **Первый запуск**: если `config.welcome` ещё нет — `active`, когда операций нет, иначе `done`. Пока `active`,
   вместо приложения показываются экраны первого запуска ([05](05-screens.md#первый-запуск)); «Готово» и «Пропустить»
   записывают `done`. Повторно не меняется.
4. **Курсы**: фоновая загрузка (не блокирует запуск), см. ниже.
5. Платформенные шаги (web: защита хранилища, хуки автобэкапа) — см. [06-platforms.md](06-platforms.md).

## Операции (transactions)

### Добавить
1. Проверка — [validateNewTransaction](02-business-rules.md#проверка-операции-financevalidatenewtransaction).
2. `id` = новый UUID, `timestamp` = сейчас.
3. Применить изменения балансов (для каждого счёта: нет счёта → ошибка «Счёт не найден: {id}»).
4. Если `debtId` — применить платёж к долгу (нет долга → «Долг не найден: {id}»); если `goalId` — к цели
   («Цель не найдена: {id}»).
5. Сохранить операцию; `config.last_account_id = accountId`.

### Изменить
1. Проверка новой версии.
2. Нет операции → «Операция не найдена».
3. Связь с долгом/целью менять нельзя (`debtId`, `goalId` должны совпасть) → «Связь с долгом или целью изменить нельзя».
4. Для платежа по долгу / пополнения цели счёт должен быть в KZT → «Долги и цели ведутся в тенге — выберите счёт в KZT».
5. Откатить влияние старой версии (балансы, долг/цель), применить новую. `id` и `timestamp` сохраняются.
   `last_account_id` не меняется.

### Удалить и отменить удаление
- Удаление — сразу, **без подтверждения**: откат балансов и долга/цели, удаление записи; показывается тост
  «Операция удалена» с кнопкой «Отменить» (дольше обычного тоста).
- «Отменить» восстанавливает ту же запись (тот же `id` и `timestamp`) и заново применяет её влияние.
  Если запись уже на месте — ничего не делать.

## Счета
- **Создать**: проверка ([accounts](02-business-rules.md#счета-accounts)); `name` обрезается; `currentBalance = initialBalance`; не в архиве.
- **Архивировать / вернуть**: нельзя архивировать последний активный счёт → «Нельзя архивировать последний активный счёт».
  Архивный счёт пропадает из выбора в формах и из капитала; операции остаются.
- **Изменить начальный остаток** — только у счёта, по которому ещё нет операций (ни одна операция не ссылается на него
  в `accountId` или `toAccountId`): так вносят, сколько на счёте сейчас, в том числе на стартовом «Наличные KZT».
  Нет счёта → «Счёт не найден»; не число → «Начальный остаток должен быть числом»; есть операции → «По счёту уже есть
  операции — остаток меняется только ими». Записывается `initialBalance = currentBalance =` новое значение (инвариант
  [01](01-data-model.md#account--счёт) сохраняется). Архивный счёт — так же.
- Другое редактирование (название, тип, валюта) и удаление счетов **не предусмотрены**; после первой операции баланс
  меняется только операциями.

## Категории
- **Создать**: проверка; `id = "cat-" + UUID`; `isDefault = false`; `order = max(order всех категорий, 0) + 1`;
  `isExcludedFromNoSpend: true` записывается только для расходной и только если включено.
- **Изменить**: название, иконка, цвет и (для расходной) флаг «не нарушает дни без трат» — записывается
  явно, в том числе `false`. Тип не меняется. Проверка уникальности исключает саму категорию.
  Флаг категории влияет только на **новые** операции; у существующих сохраняется их собственное значение.
- **Скрыть / вернуть**: нельзя скрыть последнюю активную категорию своего типа → «Нельзя скрыть последнюю категорию этого типа».
- **Удалить**: только пользовательскую (`isDefault == false`) → иначе «Стандартную категорию можно только скрыть»;
  только без операций и лимитов → иначе «Есть операции или лимиты — скройте категорию вместо удаления».

## Бюджет (лимиты)
- Ввод лимита сохраняется **автоматически**: через 500 мс после последнего изменения и при уходе из поля.
  Значение > 0 → записать лимит (`id` по [limitId](02-business-rules.md#траты-месяца-и-бюджет)), 0 / пусто → удалить запись.
  Некорректный ввод не сохраняется и подсвечивается («Введите сумму числом»); ошибка записи — «Не удалось сохранить лимит».
  Успех — отметка ✓ на 2 секунды.
- **Скопировать из прошлого месяца**: добавить результат planCopy. Сообщения: «Скопировано лимитов: N»;
  если в прошлом месяце плана нет — «Нет плана за {Месяц ГГГГ} — копировать нечего»; если всё уже задано —
  «Все лимиты уже заданы — копировать нечего».

## Долги
- **Создать**: проверка ([planning](02-business-rules.md#долги-и-цели-planning)); пустой «Остаток» = сумма долга;
  ставка необязательна (пусто — поля нет); `isClosed = false`.
- **Внести платёж** (сумма по умолчанию = `min(monthlyPayment, remainingAmount)`, дата — сегодня):
  счёт должен существовать («Счёт не найден») и быть в KZT («Долги и цели ведутся в тенге — выберите счёт в KZT»);
  долг должен существовать («Долг не найден»). Создаётся операция-расход:
  `categoryId = "cat-credit"` (если такая категория существует), `debtId`, `comment = "Платёж: {название}"`,
  `isExcludedFromNoSpend = true`.
- **Удалить**: только если по долгу нет операций → «По долгу есть платежи — сначала удалите их на главном экране».
  Подтверждение: «Удалить долг «{название}»?».

## Цели
- **Создать**: проверка; `currentAmount = 0`; `icon = "Target"`; цвет из формы (по умолчанию `#22c55e`).
- **Пополнить** (дата — сегодня): счёт в KZT (те же ошибки, что у долга); цель существует («Цель не найдена»).
  Операция-расход **без категории**: `goalId`, `comment = "Цель: {название}"`, `isExcludedFromNoSpend = true`.
- **Удалить**: только без пополнений → «В цель были пополнения — сначала удалите их на главном экране».
  Подтверждение: «Удалить цель «{название}»?».

## Курсы валют
- **Источник**: `https://al-writer.github.io/nbk-rates/latest.json` — копия официальных курсов НБ РК
  (формат — [rates.parseRatesFile](02-business-rules.md#курсы-валют-и-пересчёт-в-тенге)). Других запросов у приложения нет,
  кроме проверки новой версии на Android ([06](06-platforms.md#новая-версия)).
- **Автообновление при запуске**: если сохранённые курсы датированы сегодня — запрос не делается.
  Таймаут 8 с, без кэша. Курсы с датой **старше** сохранённых не принимаются. Любая ошибка — молча остаются сохранённые.
- **Кнопка «Обновить курсы»** — то же, но принудительно. Сообщения: «Курсы Нацбанка РК обновлены (на {дата})»
  или «Не удалось получить курсы (нет сети?). Остаются сохранённые или введённые вручную.»
- **Ручной ввод**: USD, EUR, RUB; пустое поле — курса нет; значение ≤ 0, больше 1 000 000 (`MAX_RATE`), не число или бесконечность (`1e400`) → «Некорректный курс {код}».
  Сохраняется `{ rates, date: сегодня, source: "manual" }`, сообщение «Курсы сохранены».

## Резервная копия
- **Экспорт**: файл `budget-backup-YYYY-MM-DD.json` (локальная дата), формат — [04-backup-format.md](04-backup-format.md) (с `platform` и `appVersion` своей платформы),
  JSON с отступом 2 пробела. После успешной записи — `config.last_backup_date = сейчас`.
- **Автобэкап**: после любого изменения данных (кроме config) — запись в выбранный пользователем файл,
  с задержкой 1,5 с после последнего изменения (несколько изменений подряд — одна запись). Реализация зависит от платформы ([06](06-platforms.md)).
- **Импорт (восстановление)**:
  1. Файл проверяется **сразу** при выборе (parseBackup); непригодный отклоняется: «Файл не подходит: {причина}»
     (или «Не удалось прочитать файл»).
  2. Подтверждение: описание «счетов: N, операций: N, долгов: N, целей: N», предложение сначала скачать копию,
     ввод слова `ЗАМЕНИТЬ`.
  3. Атомарная замена: очистить все таблицы и config, **кроме** локальных платформенных ключей
     (`last_backup_date`, привязка автобэкапа, статус хранилища); записать данные из файла; `seeded = true`.
     `last_account_id`, `onboarding` и `welcome` при этом удаляются (чек-лист и экраны первого запуска после импорта не
     показываются до следующего запуска, а при запуске определяются заново по наличию операций).
  4. Сообщение «Данные восстановлены ({описание})».

## Полный сброс
Подтверждение словом `СБРОС` (с предложением сначала скачать копию). Отменить запланированную запись автобэкапа;
очистить **все** таблицы и config, включая привязку файла автобэкапа (чтобы пустое состояние не перезаписало копию);
заново выполнить сид. Сообщение «Приложение сброшено». Чек-лист и экраны первого запуска появятся при следующем запуске
(`onboarding` и `welcome` удалены вместе с config).
