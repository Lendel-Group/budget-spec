# 02. Бизнес-правила и расчёты

Все формулы приложения. Эталон — `src/domain/*.ts` в PWA. Для каждой функции есть фикстуры
`fixtures/<модуль>.json` (имя функции в скобках): **реализация считается верной, только если проходит их все**.
Если текст расходится с фикстурами — правы фикстуры, а текст нужно исправить.

## Числа

### Округление
`round2(n) = floor((n + EPSILON) * 100 + 0.5) / 100` — то есть `Math.round` из JavaScript
(половина округляется **вверх, к +∞**), с поправкой `Number.EPSILON = 2⁻⁵²`.
- `round2(1.005) = 1.01`, `round2(-2.345) = -2.34`, `round2(0.1 + 0.2) = 0.3`.
- ⚠️ В Kotlin `kotlin.math.round` и `Math.rint` округляют к чётному, `BigDecimal.HALF_UP` — от нуля.
  Нужна именно семантика `Math.floor(x + 0.5)`. (finance.round2)

Округление применяется после каждого сложения денежных сумм: изменение баланса, остаток долга,
накопление цели, суммы по категориям, итоги месяца/года. Отдельные места, где округления **нет**,
отмечены ниже.

### Ввод суммы с цифровой клавиатуры (numpad)
Строка ввода, клавиши `0–9`, `.`, `backspace`. (numpad.applyNumpadKey)
- `.` — только одна; на пустой строке даёт `0.`.
- До 10 цифр в целой части, до 2 после точки.
- Ведущий ноль заменяется цифрой (`0` + `7` → `7`), `0` + `0` → `0`.
- Пустой ввод отображается как `0`; на экране точка показывается запятой.
- `parseAmount`: `''` и `'0.'` → 0, иначе число.

### Ввод лимита бюджета (budget.parsePlanInput)
Пробелы удаляются, первая запятая → точка. `''` → 0 (удалить лимит); число ≥ 0 → `round2`;
мусор или отрицательное → «некорректно» (`null`).

### Ввод сумм в формах (долг, цель, платёж, счёт, курсы)
Строка → число: запятая → точка, пробелы удаляются; пустое или нечисловое → «не число»
(в фикстурах — `null`, валидаторы трактуют его как ошибку).

## Даты (dates, period)

- Все даты — строки `YYYY-MM-DD` по **локальному** времени устройства; «сегодня» пересчитывается после полуночи
  и при возврате в приложение.
- `addDays`, `daysInMonth`, `daysLeftInMonth` (до конца месяца **включая** сегодня), `monthStart`,
  `clampDueDay` (31 → последний день короткого месяца).
- `daysBetween(a, b)` — целое число календарных дней `b − a` (planning.daysBetween).
- Листание месяцев (period): `addMonths`, `monthBounds(current, earliest, ahead)` — назад до месяца самых
  ранних данных (не позже текущего), вперёд на `ahead` месяцев; `yearBounds` — назад до года первых данных,
  вперёд до текущего года.

## Курсы валют и пересчёт в тенге

- Курс = тенге за 1 единицу валюты. Хранится в config `fx_rates` (см. [01](01-data-model.md#config--настройки-ключ--значение)).
- `convertToKzt(amount, currency, rates)`: KZT — как есть; иначе `amount × rate`; нет курса → «нет значения». **Без округления.**
- Все итоги (капитал, траты месяца, аналитика) считаются **по текущим курсам**, а не по курсу на дату операции.
- Операции и счета в валюте без курса **пропускаются** в суммах (и, где сказано, перечисляются отдельно).
- Файл курсов (rates.parseRatesFile): `{ date: "YYYY-MM-DD", rates: { USD: 503.12, ... } }`; берутся только
  USD, EUR, RUB с конечным положительным значением; если ни одной — файл недействителен.

## Капитал (finance.calculateNetWorth, accountsMissingRates)
Сумма `currentBalance × курс` по **неархивным** счетам, затем `round2`. Счета без курса не входят
и перечисляются в предупреждении «Нет курса для USD, EUR — эти счета не вошли в капитал».

## Влияние операции на балансы (finance.getBalanceDeltas)

| Тип | Изменение |
|---|---|
| expense | `accountId: −amount` |
| income | `accountId: +amount` |
| transfer | `accountId: −amount`, `toAccountId: +(toAmount ?? amount)` |

Откат (удаление, редактирование) — те же изменения с обратным знаком. Новый баланс — `round2(старый + delta)`.

### Долг и цель
- Платёж по долгу (finance.applyToDebt): `remaining = round2(remaining − amount)`; если < 0 — ошибка
  «Платёж превышает остаток долга»; `isClosed = (remaining == 0)`. Откат — `amount` с минусом (долг может снова открыться).
- Пополнение цели (finance.applyToGoal): `current = round2(current + amount)`; `isAchieved = current ≥ target`.
  Сверх цели пополнять можно. Откат может снять отметку «достигнута».

## Проверка операции (finance.validateNewTransaction)
Проверки по порядку, первая сработавшая — сообщение об ошибке:
1. `amount` не конечное или ≤ 0 → «Сумма должна быть больше нуля».
2. Перевод: нет `toAccountId` → «Не выбран счёт зачисления»; `toAccountId == accountId` →
   «Счета перевода должны различаться»; `toAmount` задан и ≤ 0 → «Сумма зачисления должна быть больше нуля».
3. Есть `debtId` или `goalId`, а тип не `expense` → «Платёж по долгу или цели должен быть расходом».
4. Не перевод, нет `categoryId`, `debtId`, `goalId` → «Выберите категорию».

## Траты месяца и бюджет

- **Траты** (finance.calculateExpensesKzt): сумма расходов в KZT; **пополнения целей не считаются тратами**
  (это сбережения), **платежи по долгам считаются**. Операции по неизвестному счёту и без курса пропускаются. `round2` в конце.
- **План месяца** (finance.sumPlannedLimits): сумма `plannedAmount` лимитов месяца, `round2`.
- **Траты по категориям** (budget.calculateCategoryTotalsKzt): то же, по `categoryId`, без операций без категории.
- **Без категории** (budget.calculateUncategorizedKzt): расходы без `categoryId` (кроме пополнений целей).
- **Итог месяца** (budget.monthBalance): если план ≤ 0 — «нечего сравнивать» (не показывается); иначе
  `diff = round2(plan − spent)`, показывается `|diff|` и «Осталось» или «Перерасход» (`diff < 0`).
- **Копирование плана** (budget.planCopy): из прошлого месяца переносятся лимиты (> 0) тех категорий,
  у которых в текущем месяце лимита ещё нет; уже заданные не перезаписываются.
- id лимита: budget.limitId; подпись месяца: budget.monthLabel («Ноябрь 2026»).

### Лимит на сегодня (finance.calculateDailyAllowance, getAllowanceStatus)
```
дней = дней до конца месяца, включая сегодня
лимит = floor((план − траты) / дней), если дней > 0 и (план − траты) > 0, иначе 0
```
Статус: **зелёный** — лимит > 2 000 ₸ («Всё в порядке»), **жёлтый** — 1…2 000 ₸ («Тратьте аккуратнее»),
**красный** — 0 («Лимит исчерпан»). Без плана (0) лимит не показывается — вместо него подсказка задать лимиты.

## Дни без трат

- Операция **нарушает** день (finance.breaksNoSpendDay) ⇔ это `expense` и `isExcludedFromNoSpend == false`.
  Доходы и переводы день не нарушают.
- `isExcludedFromNoSpend` новой операции (categories.resolveExcludedFromNoSpend): ручной выбор пользователя,
  если он был, иначе флаг категории, иначе `false`. Платежи по долгам и пополнения целей **всегда** `true`.
- **Начало учёта** (planning.getFirstTrackedDate): самая ранняя из дат создания счетов (первые 10 символов
  ISO-строки) и дат операций; если данных нет — сегодня.
- **Серия** и **чистые дни месяца** (finance.calculateNoSpendStreak): серия — подряд идущие дни без нарушений,
  считая назад от сегодня **включительно** (сегодня «чистое», пока в нём нет трат), не раньше начала учёта и
  не более 366 дней. Чистые дни месяца — дни с 1-го числа (или с начала учёта, если оно позже) по сегодня без нарушений.
- **Календарь** (planning.buildCalendar): недели с понедельника, пустые ячейки — `null`. Состояние дня:
  `future` (после сегодня) → `untracked` (до начала учёта) → `spent` (есть нарушение) → `clean`.
  Открыть (посмотреть операции дня) можно только `clean` и `spent` (planning.isCalendarDayInteractive).
- Для прошлых месяцев «чистых дней в месяце» = число ячеек `clean` в календаре этого месяца.

## Долги и цели (planning)

- **Ближайший платёж** (planning.nextDueDate): `dueDay` в текущем месяце (с поправкой на длину месяца),
  если он не раньше сегодня; иначе в следующем. Подпись: «платёж сегодня» или «платёж через N дн.».
- **План цели** (planning.calculateGoalPlan): `remaining = max(0, round2(target − current))`,
  `daysLeft = daysBetween(сегодня, targetDate)`, `months = max(1, ceil(daysLeft / 30.44))`,
  `perMonth = remaining == 0 ? 0 : ceil(remaining / months)`.
- Валидация форм — planning.debtFieldErrors, goalFieldErrors, amountFieldError (тексты ошибок — в фикстурах).
  Порядок ключей в результате = порядок проверок; «первая ошибка» = первый ключ.
- Долги и цели ведутся только в **тенге**: платёж/пополнение возможны лишь со счёта в KZT.

## Аналитика (analytics)

- **Год по месяцам** (analytics.calculateYearSummary): для каждого месяца доходы и расходы в KZT;
  переводы и пополнения целей не учитываются; `savings = income − expense` (всё через `round2`).
  Пополнение цели, таким образом, остаётся в «сбережениях».
- **Итог года** (analytics.sumYear).
- **По категориям** (analytics.calculateCategoryBreakdown) за год или месяц: суммы в KZT, `share = amount / total`
  (**без округления**), сортировка по убыванию суммы, при равенстве — по id категории, «без категории» (`null`) в конце
  при равенстве. Валюты без курса перечисляются в `skippedCurrencies` (по алфавиту). Итог совпадает с расходами того же периода.
- **Высота столбцов** (analytics.barFractions): доля от максимума, отрицательные → 0, все нули → нули.
- **Подпись оси** (analytics.compactAmount): ≥ 1 млн → «2,3 млн», ≥ 1 000 → «1,5 тыс.», иначе целое.

## История операций (history)

- **Фильтр** (history.filterTransactions): тип, счёт (перевод относится к **обоим** своим счетам), категория,
  даты `from`/`to` включительно; пустое значение — без ограничения.
- **Периоды** (history.periodRange): всё время, этот месяц, прошлый месяц, последние 30 дней (сегодня и 29 до него), свой.
- **Группы по дням** (history.groupByDay): дни от новых к старым, внутри дня — по `timestamp` убыв.
  Итог дня в KZT = доходы − расходы (переводы не считаются; платежи по долгам и пополнения целей — расходы);
  `null`, если считать нечего (только переводы или нет курса).
- **Порции** (history.takeGroups): показываются целые дни, пока не наберётся ≥ 100 операций; «Показать ещё (N)».

## Категории (categories)

- **Порядок по умолчанию** (categories.sortByDefaultOrder): сначала стандартные в порядке сида, затем
  пользовательские по `order`, при равенстве — в исходном порядке.
- **Порядок в форме «+»** (categories.sortCategoriesByUsage): по частоте использования за последние 90 дней
  (с `сегодня − 90` включительно), при равенстве — порядок по умолчанию.
- **Валидация** (categories.categoryFieldErrors): название 1–30 символов после trim, уникально без учёта регистра
  среди того же типа (для скрытой — своё сообщение); иконка выбрана; цвет `#rrggbb`.

## Счета (accounts)

- Валидация (accounts.accountFieldErrors): название непустое; начальный остаток — число (может быть отрицательным).
- **Счёт по умолчанию в форме «+»** (accounts.pickAccount): выбранный пользователем → счёт последней операции,
  если он не в архиве → первый активный → первый в списке.

## Первые шаги (onboarding.onboardingSteps)
Три шага, отмечаются автоматически по данным, в любом порядке:
1. «Добавьте счёт и остаток» — счетов больше одного или у какого-то `initialBalance ≠ 0`.
2. «Задайте лимиты» — есть хотя бы один лимит (любого месяца).
3. «Добавьте первую операцию» — есть хотя бы одна операция.

## Форматирование для показа (format)

Эталон — `Intl.NumberFormat('ru-RU')`. Фикстуры `format.json` содержат точные строки.
- Разделитель тысяч — **неразрывный пробел U+00A0**, десятичный — запятая, минус — дефис-минус `-`.
- Копейки показываются (ровно 2 знака), только если у числа есть дробная часть: `5 000`, `12,50`, `10,00` (для 10.001).
- `formatMoney` = число + U+0020 + знак валюты: `₸`, `$`, `€`, `₽`.
- `pluralRu(n, [one, few, many])` — русское склонение.
- `formatShare`: доля в процентах, округлённая; ненулевая < 0,5% → `<1%`.
- Даты: `formatDateChip` («Сегодня», «Вчера», «12 ноя»), `formatDayHeading` («Сегодня», «Вчера»,
  «3 ноября, пн», для прошлых лет — «8 марта 2025, сб»).
- Тост после сохранения (savedMessage): «Расход 5 000 ₸ сохранён», «Перевод … выполнен», при редактировании «Изменения сохранены».

## Подтверждение опасных действий (dangerConfirm)
Слово вводится без учёта регистра и пробелов по краям: `СБРОС` (полный сброс), `ЗАМЕНИТЬ` (восстановление из файла).
Латинские похожие буквы не принимаются.
