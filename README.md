# budget-spec — спецификация приложения MBT: My Budget Tracker

Источник правды о **поведении** приложения MBT (My Budget Tracker) для всех платформ:

| Платформа | Репозиторий |
|---|---|
| Web / iOS (PWA, эталон) | [Lendel-Group/PWA-Budget](https://github.com/Lendel-Group/PWA-Budget) |
| Android (Kotlin) | [Lendel-Group/android-budget](https://github.com/Lendel-Group/android-budget) |

Задача репозитория: чтобы разные реализации работали **одинаково**: одни и те же расчёты, тексты, экраны
и один формат данных (резервная копия с одной платформы открывается на другой).

## Что внутри

| Путь | Что это |
|---|---|
| [`spec/`](spec/00-overview.md) | Описание продукта: модель данных, бизнес-правила, операции, формат бэкапа, экраны, различия платформ. |
| [`fixtures/`](fixtures/README.md) | Эталонные тест-случаи «вход → ожидаемый результат» (324 шт.), сгенерированные из PWA. Обязательны для всех реализаций. |
| [`schema/`](schema/backup-v2.schema.json) | JSON Schema файла резервной копии. |
| [`screens/`](screens) | Скриншоты всех экранов PWA — визуальный референс. |
| [`tools/`](tools/README.md) | Генерация и проверка фикстур по коду PWA. |

## Как этим пользоваться

**Реализуя платформу:** читать `spec/` по порядку (00 → 06); каждую функцию из `spec/02` реализовать
и проверить на `fixtures/*.json` в тестах платформы; экспорт/импорт сверять с `spec/04` и `schema/`.

**Меняя поведение:** сначала здесь (документ, при необходимости — новые случаи в `tools/cases.ts`),
затем в PWA (перегенерировать фикстуры), затем в остальных реализациях. Подробно — [`tools/README.md`](tools/README.md).

**Приоритет при расхождениях:** фикстуры → текст `spec/` → код PWA. Найденное расхождение исправляется здесь,
а не «молча» в одной из реализаций.
