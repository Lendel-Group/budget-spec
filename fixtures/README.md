# Фикстуры: эталонные входы и выходы

Каждый файл `<модуль>.json` — набор случаев «функция + аргументы → ожидаемый результат», вычисленных
эталонной реализацией (PWA). Любая реализация (Android и др.) должна прогонять **все** случаи в своих тестах.

```json
{
  "module": "finance",
  "generatedFrom": "PWA-Budget@8916136 (v1.22.2)",
  "cases": [
    { "fn": "calculateDailyAllowance", "name": "splits remaining, floored", "args": [100000, 40000, 20], "expected": 3000 }
  ]
}
```

## Соглашения
| В JSON | Значение |
|---|---|
| `args` | Аргументы функции по порядку. Отсутствующие в конце необязательные аргументы не передаются. |
| `{ "$set": [...] }` | Множество (Set) строк. В результате — отсортировано. |
| `{ "$undefined": true }` | «Нет значения» (`undefined` в JS; в Kotlin — `null`). |
| `{ "$error": "текст" }` | Функция бросает ошибку с этим текстом. |
| поле объекта отсутствует | Необязательное поле без значения. В Kotlin-моделях — `null`. |
| `null` в аргументах числовых полей формы | Введено не число (NaN в JS). |
| `{ "$number": "Infinity" }` | Нечисловое значение double, которого нет в JSON: `"Infinity"`, `"-Infinity"`, `"NaN"`. Только в аргументах. |

- Объекты сравниваются по содержимому (порядок ключей не важен), **кроме** результатов `*FieldErrors`:
  там порядок ключей = порядок проверок (первый ключ — «первая ошибка»), его стоит проверять.
- Числа сравниваются с допуском `1e-9` (расхождения в последнем бите double допустимы, в копейках — нет).
- Имена функций и модулей — как в PWA (`src/domain/*.ts`, `src/lib/format.ts`, `src/lib/savedMessage.ts`).
  Реализация на другой платформе может называть их иначе — нужна только таблица соответствия в тестах.

## Модули
| Файл | Что покрывает |
|---|---|
| finance | округление, лимит на сегодня, серия без трат, капитал, проверка операции, балансы, долг, цель, траты |
| dates | даты, длина месяца, подписи дат |
| period | листание месяцев и лет |
| rates | разбор файла курсов |
| budget | лимиты, копирование плана, ввод лимита, траты по категориям, итог месяца |
| planning | платежи по долгам, план цели, валидация форм, начало учёта, календарь |
| analytics | год по месяцам, разбивка по категориям, график |
| history | фильтры, периоды, группировка по дням |
| categories | порядок категорий, валидация, флаг «дни без трат» |
| accounts | валидация счёта, счёт по умолчанию |
| numpad | цифровая клавиатура |
| onboarding | шаги «С чего начать» |
| dangerConfirm | слово подтверждения |
| backupValidation | проверка файла бэкапа с текстами ошибок |
| format | форматирование чисел, денег, склонения, процентов |
| savedMessage | текст тоста после сохранения |

Как добавить случаи и перегенерировать — [`tools/README.md`](../tools/README.md). Руками JSON не править.
